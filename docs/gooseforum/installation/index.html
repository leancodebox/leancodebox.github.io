安装与首次启动 ​

建议首次部署使用发行包，无需在服务器安装 Go、Node.js 或 pnpm。以下内容核对至 v0.2.122；源码构建要求以对应版本的 go.mod 和前端依赖为准。

选择发行包 ​

在 Releases 选择版本，再按系统与 CPU 下载：

系统Intel / AMD 64 位ARM 64 位
LinuxGooseForum_Linux_x86_64.tar.gzGooseForum_Linux_arm64.tar.gz
macOSGooseForum_Darwin_x86_64.tar.gzGooseForum_Darwin_arm64.tar.gz
WindowsGooseForum_Windows_x86_64.zipGooseForum_Windows_arm64.zip

Linux / macOS 可用 uname -m 查看架构：x86_64 对应 Intel / AMD，arm64 或 aarch64 对应 ARM。下载同一版本的 checksums 文件并核对压缩包 SHA-256；不要混用不同版本的校验值。

首次启动 ​

Linux x86_64 示例，在准备长期保存数据的目录中解压并运行：

sh
mkdir -p gooseforum
cd gooseforum
tar -xzf /path/to/GooseForum_Linux_x86_64.tar.gz
chmod +x GooseForum
./GooseForum serve

将 /path/to/ 换成下载目录。macOS 使用对应的 Darwin 压缩包；Windows 解压后在 PowerShell 中进入目录，运行 ./GooseForum.exe serve。

首次运行会在工作目录生成 config.toml，默认配置使用 SQLite，默认端口为 5234。打开 http://localhost:5234，以启动日志中的实际端口为准。后续启动始终使用同一工作目录，否则可能读取另一份配置或创建新数据库。

  1. 确认首页能够加载，注册自己的管理账号。
  2. 新数据库中 ID 为 1 的用户自动成为管理员；已有数据库不会因为重新部署而重新选管理员。
  3. 进入管理后台，配置站点信息并创建一个分类。
  4. 发布测试主题，验证回复、图片上传和重新登录。
  5. 按 后台初始化 完成邮件和注册政策，再按 部署 开放公网访问。

从源码构建 ​

当前源码要求 Go 1.27+。前端建议使用 Node.js 24 LTS 和 pnpm；这是本文的构建环境建议，上游 README 中的 Node.js 18 下限不足以说明所有当前依赖的要求。

sh
git clone https://github.com/leancodebox/GooseForum.git
cd GooseForum
git checkout v0.2.122
cd resource
pnpm install --frozen-lockfile
pnpm build
cd ..
go build -ldflags="-w -s" -o GooseForum .
./GooseForum serve

前端资源嵌入 Go 程序，顺序必须是先构建前端，再构建后端。只替换源码或前端目录不会更新已经编译的程序。跟踪 main 时应记录实际提交 SHA，便于复现和回退。

启动异常时先看什么 ​

  • 端口被占用：修改已有 [server] 中的 port 并重启。
  • 页面看起来像全新站点：先确认工作目录、config.toml 和数据库路径，不要重新初始化旧数据。
  • 编译要求更高 Go 版本：检查所选版本的 go.mod，或改用对应平台的发行包。
  • 数据库迁移失败：保留日志和备份，按 故障排查 处理。
