后台初始化与日常管理 ​

完成 首次启动 后，以管理员身份进入后台。推荐先确定站点身份与访问规则，再开放注册。

站点信息与公告 ​

在「设置 → 站点信息」（/admin/settings/site-info）维护名称、公开 URL、联系邮箱、Logo、描述和外部链接。公开 URL 应与访问域名及 config.toml 的 server.url 保持一致。

「设置 → 公告」用于开启和编辑站点公告；「设置 → 发帖」维护标题和正文长度、新用户冷却、每日主题上限、附件开关、数量、大小及扩展名规则。建议先用普通账号验证实际效果，避免只从管理员视角检查权限。

邮件先测试，再开启强制验证 ​

  1. 在「设置 → 邮件」（/admin/settings/mail）填写 SMTP 主机、端口、账号、密码或授权码、SSL 和发件人信息。
  2. 使用测试邮件功能检查当前表单值，并到收件箱确认送达；测试可以使用尚未保存的值，测试成功后仍需保存配置。
  3. 在「设置 → 安全」配置注册、邮箱验证和允许注册的邮箱域名。
  4. 用一个新邮箱走完注册、验证、登录和重置密码流程。

需要本站发送验证邮件的新账号，在 SMTP 未配置时会被拒绝创建。SMTP 接受邮件也不代表最终送达，需要同时检查垃圾邮件、发件服务的退信与发送记录。

分类、可见性与权限 ​

在 /admin/categories 创建分类并设置名称、标识、描述、颜色和排序。分类是否公开由 everyone 权限组是否可读决定；受限分类需要明确允许访问的组。

管理事项使用入口核对重点
分类内容与版主分类管理版主可按用户名或用户 ID 查找
分类访问范围分类访问设置保留至少一个有效可读组，使用游客和普通账号验证
后台管理权限/admin/roles按职责分配权限；完整管理员拥有更广权限
发帖与附件限制/admin/settings/posting检查新用户、普通用户的实际限制

主题管理员可编辑分类和管理版主；角色管理员可管理分类访问权限，但不因此获得分类编辑权限。存在多分类主题时，公开分类转为受限分类可能被阻止，应先处理关联主题，不能把保存失败当作已经生效。

第三方登录与本站 OIDC ​

这两个入口解决不同问题：

  • OAuth 登录（/admin/settings/oauth）：让用户使用 GitHub、Google、Discord 或自定义 OIDC 身份登录本站。
  • OIDC 提供方（/admin/settings/oidc-provider）：让其他应用使用 GooseForum 账号登录。

配置第三方登录时，复制后台显示的回调地址到提供商控制台，填写 Client ID 和 Secret 后启用。修改域名或 HTTPS 配置后重新核对回调地址；不要凭经验拼接路径。

第三方邮箱与现有账号冲突时不会自动绑定。已有用户应先登录原账号，再主动绑定第三方身份。关闭注册后，已有账号仍可登录和绑定，但首次创建第三方账号同样受注册政策限制。

上线验收 ​

以游客、普通用户、管理员三个视角检查：首页与分类可见性、注册验证、登录退出、主题与回复、附件访问、举报或管理入口。使用站点真实 HTTPS 域名测试第三方回调和邮件链接。
