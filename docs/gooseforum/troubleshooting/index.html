故障排查 ​

先记录版本、运行目录、数据库类型、最近变更和错误时间，再查看相应日志。分享日志前移除密码、Cookie、令牌、连接串和邮件凭据。

服务无法启动或出现新空站点 ​

使用 systemd 时查看 systemctl status gooseforum 和 journalctl -u gooseforum -n 100 --no-pager。核对端口占用、TOML 语法、文件权限与数据库可用性。

如果服务能启动却没有原来的主题，检查 WorkingDirectory、实际加载的 config.toml、SQLite 路径或外部数据库名。不要在尚未确认路径时继续注册、迁移或覆盖数据库。

注册失败、验证邮件不到或频繁限流 ​

症状检查方向
新账号无法创建注册开关、邮箱域名精确匹配、SMTP 是否配置
OAuth 首次登录失败上游是否提供有效邮箱、是否与已有账号冲突、是否允许注册
所有用户像共用一个 IP反代地址是否列入 server.trustedProxies
邮件测试成功但实际未生效测试使用当前表单值，确认之后已保存
收到 SMTP 成功却没邮件收件箱、垃圾邮件、发送记录和退信，成功提交不等于送达
待验证用户无法登录正确密码与验证码可触发重发，仍受冷却与邮件配额约束

先解决配置和投递问题，再重试注册或登录；不要通过反复重启清空限额来代替定位原因。具体默认值见 账号安全。

双因素认证失败 ​

检查服务器和手机时间、是否重复使用上一枚验证码、当前挑战是否已经过期。服务重启会清空挑战，需要重新开始登录。

升级后所有 MFA 用户同时失败，优先确认是否误改了 [app].secretKey 或旧 signingKey 的值。恢复原密钥，不能靠生成新密钥解密旧数据。丢失个人验证器按 恢复流程 处理，改密码不会移除 MFA。

图片或附件异常 ​

数据库存储时核对数据库连接和文件记录；S3 存储时分别检查服务端 endpoint、凭据、桶、浏览器可访问的 publicUrl 与对象权限。

直传请求失败时检查浏览器网络面板中的预签名 PUT，桶 CORS 是否允许站点来源、PUT 和 Content-Type。上传超时还需核对应用 HTTP 超时、文件大小限制及代理限制。

更新后页面不一致 ​

确认前端与后端属于同一构建，实际运行的可执行文件已更新，代理没有长期缓存 HTML 或状态接口。先保存未提交内容，再使用页面刷新入口。仅在源码目录运行前端构建，不会修改旧二进制中的资源。

管理员账号恢复 ​

服务器管理员可在原运行目录使用以下命令；42 是占位用户 ID，必须先核对目标用户：

sh
./GooseForum set-user-admin 42
./GooseForum set-user-password 42 'REPLACE_WITH_A_NEW_PASSWORD'

只运行需要的命令，不要原样使用示例密码。密码作为命令行参数可能进入 shell 历史和进程参数，应在受控维护终端操作。独立 CLI 改密后，服务内认证缓存最多有 15 秒失效延迟。上述命令不重置 MFA。

报告问题时附带的信息 ​

提供版本或提交 SHA、系统和 CPU、数据库类型、复现步骤、预期与实际结果、脱敏日志。界面问题附带浏览器版本和失败请求状态码。源码与问题反馈入口：GooseForum。
