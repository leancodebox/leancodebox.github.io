生产部署 ​

以下是 Linux + systemd + 同机 Caddy 的部署示例，需要已有域名、服务器及已安装的 Caddy。路径、账号和域名均需按实际环境调整；这些服务文件是本文建议，并非 GooseForum 自带安装器。

固定目录与运行身份 ​

建议将程序、config.toml、storage/ 放在 /opt/gooseforum，使用专用系统账号 gooseforum 运行。先创建账号与目录，将发行包解压到该目录，并让运行账号拥有所需读写权限。不要用 Web 根目录公开配置或数据库。

从该目录首次运行程序生成配置，停止程序后修改已有配置段：

toml
[app]
env = "production"
# 保留原有 secretKey，不要用本片段覆盖整个文件。

[server]
url = "https://forum.example.com"
port = 5234
trustedProxies = ["127.0.0.1"]

[log]
type = "stdout"

同一 TOML 段不能重复声明。此片段省略了数据库和其他现有设置，请合并修改。限制 config.toml 权限，例如 chmod 600 config.toml，并确认文件归运行账号所有。

后端监听范围

生产模式的 HTTP 服务监听所有接口。应通过防火墙或安全组限制 5234 的外部访问，公网流量只经 HTTPS 反代进入；server.url 不会改变监听地址。

配置 systemd ​

将以下示例保存为 /etc/systemd/system/gooseforum.service：

ini
[Unit]
Description=GooseForum
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=gooseforum
Group=gooseforum
WorkingDirectory=/opt/gooseforum
ExecStart=/opt/gooseforum/GooseForum serve
Restart=on-failure
RestartSec=5
UMask=0077

[Install]
WantedBy=multi-user.target

WorkingDirectory 决定配置与相对数据路径。服务用户必须能访问数据库、日志和备份目录。安装服务后：

sh
sudo systemctl daemon-reload
sudo systemctl enable --now gooseforum
sudo systemctl status gooseforum
sudo journalctl -u gooseforum -n 100 --no-pager

配置 HTTPS 反代 ​

把下面的站点块加入 Caddyfile，替换为实际域名：

text
forum.example.com {
    reverse_proxy 127.0.0.1:5234
}

确保域名解析到服务器，并允许证书签发和访问所需的 80 / 443 端口。使用 Caddy 配置校验命令 检查后再重载；反代配置参考 Caddy 官方指南。若代理位于容器或另一台机器，后端地址和 trustedProxies 都需要随拓扑调整。

验证部署 ​

sh
curl --fail http://127.0.0.1:5234/api/forum/status
curl --fail https://forum.example.com/api/forum/status

状态接口用于确认 HTTP 与版本检测路径可达，不代表数据库、邮件和对象存储全部健康。还需用真实域名验证注册、登录、发帖、图片、邮件链接和第三方回调。

上传大文件失败时，同时检查应用上传限制、HTTP 读写超时与反代限制。使用 S3 直传时还要验证桶 CORS，见 配置。

运行维护 ​

保持一个服务实例，按 备份与升级 建立恢复流程。修改监听端口、数据库、日志、缓存后重启；不要因为文件支持热重载就认为所有运行状态都会重新初始化。
