注册与账号安全 ​

当前注册计数、认证缓存和 MFA 挑战包含进程内状态，按单实例部署使用。不能仅把多个进程接到同一数据库就认为这些状态已经共享。

注册与邮件配额 ​

「设置 → 安全」可设置每小时注册请求限额。默认值如下：

维度注册请求密码重置与验证邮件共享配额
每个可信 IP520
每个目标邮箱33
全站100200

注册限额配置中的 0 表示关闭对应限额。注册计数针对通过政策与凭据校验的请求，并非最终创建成功的账号数；内存窗口从首次请求起持续一小时，重启会清空，不能用于多实例共享限流。验证邮件重发另有每分钟一次、每天三次的账号限制。

邮箱允许域名采用精确匹配：example.com 不包含 sub.example.com。开启验证或域名限制后，新账号会保留自己的验证要求，切换 OAuth 登录不会绕过它。

反向代理后的真实 IP ​

只有 server.trustedProxies 中的代理 IP / CIDR 才会被信任。以同机 IPv4 反代为例，在已有 [server] 段增加：

toml
trustedProxies = ["127.0.0.1"]

未配置时不信任转发头，经过代理的请求可能都按代理 IP 计数。不要为方便填写所有来源；容器或独立代理应填写实际受控代理地址，并限制后端直接访问。完整示例见 部署。

启用双因素认证 ​

GooseForum 使用标准 TOTP（6 位、30 秒）和 10 个一次性恢复码。密码登录与 OAuth 登录都需要通过已启用的第二因素。

  1. 在账号设置输入本地账号密码，开始绑定验证器。
  2. 扫描二维码或手工录入密钥，输入动态验证码完成确认；确认前不会生效。
  3. 保存只显示一次的恢复码，可下载后离线妥善保存。
  4. 重新登录验证。启用、关闭或重新生成恢复码会撤销所有设备的登录。

第三方登录用户需先绑定并验证邮箱，再通过重置密码流程设置本地密码。密码重置本身不会关闭 MFA。恢复码只能使用一次，重新生成后旧恢复码全部失效。

系统密钥与服务器时钟 ​

[app].secretKey 用于派生 MFA 加密密钥，应保留首次生成的随机值并与数据库一起备份。旧配置在未设置新字段时兼容 signingKey；重命名字段时必须保留原值。

不要替换成自选口令或在已有绑定用户时重新生成密钥。密钥丢失或格式损坏会导致验证失败，不能通过重建配置自动恢复。服务器与验证器都应保持正确时间。

MFA 挑战 5 分钟过期，待确认绑定 10 分钟过期；重启服务后需要重新登录或开始绑定。验证码不可重复使用，验证失败后也不要反复提交同一码。

丢失验证器如何恢复 ​

先使用未消费的恢复码。若全部第二因素丢失，完整管理员可在「用户 → 编辑 → 账号设置」核验身份、填写原因并确认重置；操作会撤销会话并记录审计。普通用户管理员没有此权限，管理员也不能用该入口重置自己的 MFA。

当前没有 MFA 重置 CLI，也没有通过邮件直接绕过第二因素的恢复入口。部署时应先保存系统密钥与恢复码，避免把改密码误当成 MFA 恢复方案。
