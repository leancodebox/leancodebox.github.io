备份、恢复与日志 ​

以下接口已存在于核对的源码提交 96c86ae，旧构建可能不具备。先查看运行实例的 /api/docs，按 安装 更新后再使用。

数据目录与备份范围 ​

数据目录包含 rooster.db 和 logs/。ROOSTER_DATA_DIR 可显式设置路径，否则使用系统用户配置目录下的 Rooster。

方式包含不包含
GET /api/export带版本的任务定义 JSON、环境变量执行历史和日志；不是完整恢复备份
GET /api/backup一致性 SQLite 快照，包含已提交 WAL 数据、任务与执行元数据日志文件
单独保存 logs/当前与轮转日志任务配置和执行数据库

导出与快照可能含环境变量中的密钥，应保存在私有目录。不要直接复制正在写入的 rooster.db 主文件来代替一致性快照。

下载在线快照 ​

POSIX shell 示例，创建新的私有备份目录：

sh
export ROOSTER_BASE_URL=http://127.0.0.1:9090
umask 077
BACKUP_DIR=$(mktemp -d "$HOME/rooster-backup.XXXXXX")
curl --fail "$ROOSTER_BASE_URL/api/export" -o "$BACKUP_DIR/tasks.json"
curl --fail "$ROOSTER_BASE_URL/api/backup" -o "$BACKUP_DIR/rooster.db"
printf '%s\n' "$BACKUP_DIR"

检查每条下载命令成功后再使用文件。每次使用新目录，避免覆盖上一份有效备份；需要日志时另行保存 logs/。

离线恢复到新目录 ​

在对应版本的源码根目录运行，替换备份与目标路径：

sh
go run ./cmd/rooster-restore \
  -backup /path/to/backup/rooster.db \
  -destination /path/to/new-rooster-data

目标目录必须尚不存在，父目录应已存在。恢复命令不会覆盖现有数据目录，也不会执行任务。恢复结果具有以下行为：

  • 所有任务设为停用。
  • 中断的执行记录标记失败，日志路径调整到新目录。
  • 日志文件不会从快照恢复，需要另外保留归档。
  • 带非空 WAL 的原始数据库来源会被拒绝，使用下载的独立快照。

使用新目录和独立端口启动实例，检查任务配置、环境变量和历史，再手动验证任务。确认后逐项启用；迁移时先退出旧实例，避免两套实例同时运行同一业务任务。

当前日志与轮转归档 ​

日志在 20 MB 时轮转，保留三个压缩备份。普通日志接口只返回当前文件最后 64 KiB，不能凭页面上日志开头判断执行没有更早输出。

请求返回内容
GET /api/executions/{id}/logs当前日志尾部
GET /api/executions/{id}/logs?download=1完整当前文件，不含轮转归档
GET /api/executions/{id}/logfiles可用归档名称和大小
GET /api/executions/{id}/logs?archive={name}解压归档的最后 64 KiB，解压上限 32 MiB
GET /api/executions/{id}/logs?archive={name}&download=1原始压缩归档

只使用 logfiles 返回的名称，并对查询参数做 URL 编码。刚派发执行时日志文件可能暂未创建，短暂 404 应结合执行状态判断。

清理历史：先预览 ​

sh
curl --fail-with-body "$ROOSTER_BASE_URL/api/maintenance/retention" \
  -H 'Content-Type: application/json' \
  --data '{"days":30,"keepPerTask":100,"dryRun":true}'

只筛选已结束、早于截止时间，且不属于每个任务最新保留条数内的记录，活动执行不参与。days 范围 1–36500，keepPerTask 至少 1；发送 {} 使用上述默认值并预览。

检查返回的 candidates、files、bytes、errors，备份后才把同一请求的 dryRun 改为 false 执行删除。即使 HTTP 为 200，也要检查 errors：文件删除和记录删除不是原子操作，部分失败可能已经删除某些日志。files 与 bytes 表示计划，不保证实际释放空间。

当前没有自动清理日程或总磁盘配额。日志轮转限制单个执行文件，不等于整个数据目录不会继续增长。
