Agent 与 HTTP API ​

API 文档嵌入程序，优先读取当前运行实例的 /api/docs，避免用新文档调用旧程序。所有示例均使用本地地址，请替换为启动日志中的实际端口。

发现实例与读取契约 ​

sh
export ROOSTER_BASE_URL=http://127.0.0.1:9090
curl --fail "$ROOSTER_BASE_URL/api/health"
curl --fail "$ROOSTER_BASE_URL/api/skill"
curl --fail "$ROOSTER_BASE_URL/api/docs"
curl --fail "$ROOSTER_BASE_URL/api/tasks"

健康响应为 {"status":"ok"}。Skill 说明操作流程，API 文档说明字段、响应和错误。控制台顶部的「Agent 接入」也可复制这些入口和当前实例地址。

如需安装到 Codex 默认技能目录，可先检查该目录是否已有自定义内容，再保存：

sh
mkdir -p ~/.codex/skills/rooster/references
curl --fail "$ROOSTER_BASE_URL/api/skill" -o ~/.codex/skills/rooster/SKILL.md
curl --fail "$ROOSTER_BASE_URL/api/docs" -o ~/.codex/skills/rooster/references/api.md

创建一个停用的测试任务 ​

sh
curl --fail-with-body "$ROOSTER_BASE_URL/api/tasks" \
  -H 'Content-Type: application/json' \
  --data '{"name":"hourly-check","kind":"scheduled","enabled":false,"commandMode":"shell","command":"echo ready","schedule":"0 * * * *","overlapPolicy":"skip","restartPolicy":"never"}'

成功返回 201 和任务对象。将响应中的 id 赋给 TASK_ID，不要使用任务名称定位，因为名称不唯一。

sh
TASK_ID='replace-with-task-id'
curl --fail-with-body -X POST "$ROOSTER_BASE_URL/api/tasks/$TASK_ID/executions"
curl --fail-with-body "$ROOSTER_BASE_URL/api/tasks/$TASK_ID/executions?limit=200"

运行请求返回 202 和执行对象，仅代表请求已接受。按返回的执行 id 检查历史，直到进入 succeeded、failed 或 canceled，再判断结果。启动失败也可能返回 422 但已留下失败记录，重试前先查历史。

日志、启停与配置更新 ​

sh
EXECUTION_ID='replace-with-execution-id'
curl --fail "$ROOSTER_BASE_URL/api/executions/$EXECUTION_ID/logs"
curl --fail-with-body -X POST "$ROOSTER_BASE_URL/api/tasks/$TASK_ID/enable"
操作方法与路径注意
停用自动运行POST /api/tasks/{id}/disable定时任务已有执行不会终止
停止某次执行POST /api/executions/{id}/stop异步，返回 202 后继续检查
更新配置PUT /api/tasks/{id}完整替换，先停用并停止执行
删除任务DELETE /api/tasks/{id}同样要求无自动启用和活动执行；成功 204 无正文
执行历史GET /api/tasks/{id}/executions?limit=50最新在前，合法 limit 为 1–200

PUT 省略的配置会回到零值或默认值，不支持 PATCH。保持原 kind，不要把任务类型当作可编辑字段。请求使用 camelCase，未知字段会被拒绝。

错误与重试 ​

  • 404：目标或日志不存在；停止已结束执行也可能返回它。
  • 409：重叠执行或并发容量冲突。
  • 422：JSON、字段、Cron、生命周期前置条件、启动或存储错误。

大多数操作错误返回 {"error":"..."}，但路由错误可能为纯文本，先检查状态码再解析。没有幂等键和批量接口；创建或运行遇到连接中断时，先读取当前状态，避免盲目重试造成重复任务或执行。
