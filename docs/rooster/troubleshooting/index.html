故障排查 ​

排查时记录提交版本、启动方式、实际监听地址、数据目录、任务 ID 和执行 ID。任务名称不是唯一标识，Agent 或 API 操作应使用 ID。

9090 打不开或出现空任务列表 ​

先看 rooster ready 日志。9090 被占用时会尝试后续 100 个端口，浏览器和 Agent 需要使用实际地址。执行 curl --fail http://127.0.0.1:实际端口/api/health 确认服务可达。

能打开但数据为空时，检查是否换了系统用户、ROOSTER_DATA_DIR 或启动方式。开发实例与日常实例应隔离，不能通过重复创建任务来掩盖目录错误。

终端正常，任务却提示找不到程序 ​

核对工作目录、程序绝对路径、参数拆分、Shell 模式与 PATH。Rooster 使用继承的登录环境缓存，托盘启动和当前终端不一定相同。将依赖明确写成任务环境变量，并使用可执行文件和目录的绝对路径。

exec 不解析管道和重定向。需要 |、> 或 shell 变量展开时选择 shell，并核对所选 shell 的语法。

常驻任务反复重启，随后被停用 ​

检查每次执行退出码、时长、错误和日志。运行不足默认 10 秒也会被守护器计为失败，连续失败默认达到 3 次后停用。maxRetries=0 使用默认值，不是无限重试。

如果命令本来就应快速结束，应使用定时任务；如果是服务启动失败，先手动验证命令，再启用守护。不要只增加重试次数而忽略启动错误。

Cron 没有触发或重复运行 ​

确认任务启用、表达式为五字段、进程时区符合预期，并查看未来五次触发时间。需要固定时区可使用 CRON_TZ=Asia/Shanghai 前缀。

skip 会阻止与已有执行重叠，parallel 可能产生多个活动执行。运行状态只描述其中一个时，应查看完整历史。实例并发上限也可能拒绝新的执行。

已停用，为什么命令还在运行 ​

停用定时任务只取消后续触发，已有执行继续；需要停止对应执行 ID。常驻任务的手动执行也可能需要单独停止。停止请求是异步的，等待执行进入终态后再编辑或删除。

配置只读或返回 422 时，先确认任务已停用且没有活动执行。PUT 是完整替换，不支持变更 kind。

API 成功返回但任务失败 ​

202 仅表示接受请求，不是成功完成。根据返回执行 ID 查询历史，查看 status、exitCode 和 error。超时限制触发时错误可为 context deadline exceeded。

创建或运行请求中断后先查询状态再重试，API 没有幂等键，盲目重试可能重复执行。

日志缺失或磁盘持续增长 ​

日志接口仅展示当前文件最后 64 KiB。较早输出可能已轮转，使用归档接口读取。刚启动时文件可能尚未创建，恢复快照后日志也不会自动恢复。

20 MB 轮转和三个备份是单个日志的限制，不是全局容量限制。按 备份与日志 预览并执行历史清理，检查响应中的错误。

恢复命令拒绝目标目录 ​

恢复只能写入尚不存在的新目录，不能覆盖旧实例。源应为 /api/backup 下载的独立快照，带非空 WAL 的在线数据库副本会被拒绝。完整步骤见 恢复指南。

报告问题时附上脱敏配置、错误、任务与执行 ID 及复现步骤，移除环境变量中的密钥：Rooster Issues。
