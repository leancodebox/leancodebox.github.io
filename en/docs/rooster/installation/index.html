Installation and runtime ​

As of 2026-11-15, the repository has no published GitHub Release downloads. Build from source; this guide targets commit 96c86ae.

Build the daemon ​

Prepare Go 1.25+, Node.js and pnpm. This guide recommends Node.js 24 LTS. The daemon provides the complete web console without launching the native tray.

sh
git clone https://github.com/leancodebox/rooster.git
cd rooster
git checkout 96c86ae62c530da51cd6cd0f7b37b3d6fb7e89be
cd web
pnpm install --frozen-lockfile
pnpm build
cd ..
go build -o roosterd ./cmd/roosterd
./roosterd

On Windows, build with go build -o roosterd.exe ./cmd/roosterd, then run ./roosterd.exe.

The preferred URL is http://127.0.0.1:9090. If occupied, Rooster tries the next 100 ports. Use the actual address in the rooster ready startup log. In the console, manually run an echo ready task and check its history and logs.

Native tray and macOS packaging ​

The tray uses Fyne and requires the platform's graphical development dependencies. After building the frontend, run from the repository:

sh
go run ./cmd/rooster

make build builds the frontend, daemon and tray, so it also requires tray dependencies. For a daemon-only installation, use the standalone Go build above.

On macOS, install the Fyne packaging tool and platform dependencies, then use make package-darwin to create Rooster.app. ./build-macos.sh packages and replaces the desktop application. Quit the old instance before replacing it.

Explicit address and isolated data ​

POSIX shell:

sh
ROOSTER_DATA_DIR="$HOME/rooster-dev-data" \
ROOSTER_LISTEN=127.0.0.1:19090 \
./roosterd

PowerShell:

powershell
$env:ROOSTER_DATA_DIR = "$HOME/rooster-dev-data"
$env:ROOSTER_LISTEN = "127.0.0.1:19090"
./roosterd.exe

By default, data lives in Rooster under the OS user configuration directory. An explicit ROOSTER_DATA_DIR keeps different launch methods pointed at the same data. Use a separate directory and port for development to avoid running everyday tasks accidentally.

Frontend development and updates ​

cd web && pnpm dev starts the development server, proxying API requests to 127.0.0.1:9090 by default. Adjust the proxy if the backend uses another port.

Production assets are embedded in Go. After frontend changes, run pnpm build, rebuild the Go program and restart it. Refreshing a browser cannot load new assets into an old executable.

Local access ​

The server binds to loopback by default and has no remote authentication layer. Commands run with the Rooster process user's privileges. Keep access local and inspect commands created by agents. Continue with task management.
