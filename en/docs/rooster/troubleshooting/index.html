Troubleshooting ​

Record the commit, launch method, actual listening address, data directory, task ID and execution ID. Names are not unique; API and agent operations should use IDs.

Port 9090 does not respond or tasks are missing ​

Read the rooster ready log first. If 9090 is occupied, Rooster tries the next 100 ports. The browser and agent must use the actual address. Check /api/health on that port with curl.

If the console works but is empty, check the OS user, ROOSTER_DATA_DIR and launch method. Keep development and everyday instances separate rather than recreating tasks to hide a directory mismatch.

A command works in a terminal but is not found by Rooster ​

Check the working directory, absolute executable path, argument separation, command mode and PATH. Rooster inherits a cached login environment; tray startup may differ from your current terminal. Specify task environment overrides and absolute paths where necessary.

exec does not interpret pipes or redirection. Use shell for |, > or shell variable expansion, checking syntax for the chosen shell.

A resident task keeps restarting and becomes disabled ​

Inspect exit codes, runtime, errors and logs. A run shorter than the default ten seconds counts as a supervisor failure. The default limit is three consecutive failures. maxRetries=0 uses the default, not unlimited retries.

If the command should finish quickly, use a scheduled task. If a service fails to start, verify it manually before enabling supervision. Increasing retries does not fix the underlying launch failure.

Cron is missed or runs overlap ​

Check that the task is enabled, the expression has five fields, the process timezone is correct and the next five trigger times match expectations. Use CRON_TZ=Asia/Shanghai when an explicit timezone is needed.

skip blocks overlapping execution, while parallel permits several active runs. Runtime state can describe only one active execution, so inspect history for all of them. Instance limits can also reject new runs.

A disabled task is still running ​

Disabling a scheduled task cancels future triggers, not an existing execution. Stop the execution ID separately. Manually started resident executions can also require an explicit stop. Stopping is asynchronous: wait for a terminal state before editing or deleting.

For read-only configuration or 422 on edits, confirm the task is disabled and has no active executions. PUT fully replaces configuration and cannot change kind.

A successful API response is followed by task failure ​

202 means accepted, not successfully completed. Find the returned execution ID in history and inspect status, exitCode and error. A timeout can report context deadline exceeded.

After a connection loss during create or run, inspect state before retrying. There is no idempotency key, and blind retries can duplicate work.

Missing logs or growing disk usage ​

The log endpoint shows only the last 64 KiB of the current file. Earlier output may be in archives. A new execution may not have created its log yet, and restored snapshots do not restore log files.

The 20 MB threshold and three backups apply per log, not globally. Preview retention using backup and logs, then inspect errors when applying cleanup.

Restore rejects the destination ​

Restore requires a new directory and never overwrites an existing instance. The source should be the standalone snapshot downloaded from /api/backup; a copy with a nonempty WAL is rejected. Follow the recovery procedure.

Report sanitized configuration, errors, task/execution IDs and reproduction steps at Rooster Issues. Remove secrets from environment values.
